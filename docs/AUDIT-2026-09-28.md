**Confirmed defects, ordered by priority**

1. **P1 — Completing training can overwrite a new or replacement workspace.**

   Sources: [App.tsx:671](/Users/davidbachman/Documents/BackpropBuilder/src/App.tsx:671), [App.tsx:692](/Users/davidbachman/Documents/BackpropBuilder/src/App.tsx:692), [App.tsx:484](/Users/davidbachman/Documents/BackpropBuilder/src/App.tsx:484).

   A run retains its original graph and later publishes it unconditionally. File → New, import, undo, and canvas mutations remain available, and graph replacement does not cancel or invalidate that run. A real App test started two epochs on Starter, chose New, verified an empty canvas, and then observed the old model return when training finished. Edits made in the replacement workspace can therefore be lost.

   Fix: give each workspace/run a generation identifier; abort on workspace replacement and reject stale asynchronous results before every publish. Guard or coordinate editing while a run owns the model. Cover inference as well, since it also publishes asynchronously. Add a regression test that starts a run, replaces the graph, and verifies the replacement survives completion.

2. **P1 — Tensor batching can silently change the model's mathematics.**

   Source: [tensorTraining.ts:127](/Users/davidbachman/Documents/BackpropBuilder/src/domain/tensorTraining.ts:127).

   Ordinary TensorFlow broadcasting treats the newly added batch axis as a feature axis. Reproduction: use the Linear preset, change its weight to `{shape:[2],data:[1,2]}`, and evaluate the first two examples. Graph validation succeeds. Mean trace gradients are `[-4.995, 0.09]`, while tensor gradients are `[-5.3279996, -0.2520002]`. Scalar features have shape `[batch]`, which accidentally aligns with the two weight coordinates. Batch size one instead exposes a target-reshape failure.

   Fix: align per-example shapes separately from batch dimensions, preserving axis provenance throughout arithmetic and target broadcasting. Add parity tests for scalar-to-vector/matrix broadcasting at batch sizes 1, 2, and a size unequal to the feature width.

3. **P2 — Tensor inference misdecodes binary datasets with two output logits, and training fails.**

   Sources: [tensorTraining.ts:222](/Users/davidbachman/Documents/BackpropBuilder/src/domain/tensorTraining.ts:222), [tensorTraining.ts:255](/Users/davidbachman/Documents/BackpropBuilder/src/domain/tensorTraining.ts:255).

   The implementation assumes every binary dataset uses a single probability. The built-in Playground model instead uses two logits and cross entropy. Tensor training with batch size two fails during initial evaluation with `Size(2) must match the product of shape 2,1,2`. Setting the final biases to `[-10,10]` also demonstrates wrong inference: trace predicts class 1, tensor predicts class 0, and accuracy changes from 0.375 to 0.625 for the same model.

   Fix: choose argmax versus probability threshold using the loss and output shape. Test both sigmoid/BCE and two-logit/cross-entropy models on binary datasets.

4. **P2 — Inline edits of projected neuron weights appear to work but do not change the model.**

   Sources: [BuilderNode.tsx:253](/Users/davidbachman/Documents/BackpropBuilder/src/components/BuilderNode.tsx:253), [App.tsx:1659](/Users/davidbachman/Documents/BackpropBuilder/src/App.tsx:1659).

   Projected nodes use synthetic IDs such as `inspect:…:w0`. Their inline controls pass those IDs directly to the canonical node updater, which finds no matching model node. In a real App probe, entering `42` into a projected decoder weight left the canonical tensor coordinate at `0.12621368371146552`; the local text draft displayed the edited value.

   Fix: resolve `projection.bindings` and update the corresponding tensor coordinate. Apply the same mapping policy to other projected editing controls, or make unsupported controls explicitly read-only.

5. **P2 — Canvas operations can silently restore old learning rates and training settings.**

   Source: [GraphCanvas.tsx:658](/Users/davidbachman/Documents/BackpropBuilder/src/components/GraphCanvas.tsx:658).

   The node synchronization key omits top-level learning rate and training settings. When only those change, synchronization returns early and keeps callbacks that captured an older graph. Reproduced by rendering an Add block at learning rate `0.1`, rerendering at `0.25`, and using its add-input control: the emitted graph reverted to `0.1`.

   Fix: refresh callbacks independently of geometry synchronization, or have graph-changing callbacks operate on current state. Regression tests should change settings before inline graph edits and confirm the settings survive.

6. **P2 — Editing a model leaves old inference results displayed as current.**

   Sources: [App.tsx:843](/Users/davidbachman/Documents/BackpropBuilder/src/App.tsx:843), [App.tsx:874](/Users/davidbachman/Documents/BackpropBuilder/src/App.tsx:874), [App.tsx:918](/Users/davidbachman/Documents/BackpropBuilder/src/App.tsx:918).

   Several direct update handlers invalidate execution values but leave `inferenceResult` intact. Browser reproduction: train Starter for 10 epochs, run held-out inference, then change its weight to `-10`. The panel still reports **100.0% accuracy / 0.040 loss**. Running inference again changes it to **0.0% / 0.478**. The old result has no stale marker.

   Fix: centralize computational-edit invalidation and clear inference results, or associate reports with a model revision and visibly mark older reports. Use the same mechanism for parameter, activation, loss, and dataset changes.

7. **P2 — PyTorch exports cannot reload an original CSV containing an explicit split column.**

   Sources: [customCsv.ts:23](/Users/davidbachman/Documents/BackpropBuilder/src/domain/customCsv.ts:23), [pytorchExport.ts:211](/Users/davidbachman/Documents/BackpropBuilder/src/domain/pytorchExport.ts:211).

   Import removes the split column, but the generated Python loader expects that reduced width when reading the original file. The valid input `x,target,split` with rows `1,2,train`, `2,4,test`, and `3,6,train` imports successfully and then fails in exported Python with `ValueError: CSV row 1 has the wrong number of columns`.

   Fix: retain split-column metadata and reproduce its removal in Python, or export a normalized companion dataset. Test the exact original CSV end to end.

8. **P2 — Exported evaluation reports regularization penalties as prediction loss.**

   Sources: [pytorchExport.ts:270](/Users/davidbachman/Documents/BackpropBuilder/src/domain/pytorchExport.ts:270), [datasetTraining.ts:87](/Users/davidbachman/Documents/BackpropBuilder/src/domain/datasetTraining.ts:87).

   In-app evaluation subtracts the parameter penalty; exported evaluation returns the penalized training objective. For the same Linear model with L2 strength 10, the app reports train loss **3.1736533333**, whereas Python reports **48.1736533333**. The difference is exactly the penalty of 45. Held-out/test reporting is affected too.

   Fix: export distinct data-loss and optimization-objective calculations. Compare app and exported train/test metrics for regularized models.

9. **P2 — An unused parameter makes a valid exported program crash.**

   Sources: [pytorchExport.ts:294](/Users/davidbachman/Documents/BackpropBuilder/src/domain/pytorchExport.ts:294), [pytorchExport.ts:306](/Users/davidbachman/Documents/BackpropBuilder/src/domain/pytorchExport.ts:306).

   An optimizer is created for all Weight/Bias nodes, even when no parameter influences the loss. A graph with dataset features connected directly to Loss, targets through Target, and an unused Weight exports successfully, then crashes at `loss.backward()` because the loss has no gradient function.

   Fix: select parameters from the loss dependency graph and handle an empty differentiable parameter set, or check `loss.requires_grad`. Keep incomplete/disconnected workspaces exportable where otherwise supported.

10. **P2 — Tensor sequence metrics can exceed 100% accuracy.**

    Source: [tensorTraining.ts:223](/Users/davidbachman/Documents/BackpropBuilder/src/domain/tensorTraining.ts:223).

    `TensorGraph.evaluate()` sums correct tokens but counts examples unless the dataset is specifically custom language text. Evaluating the Decoder preset's first two three-token examples returns `accuracy: 3` (300%); `inference()` returns the correct `1`.

    Fix: count target positions for built-in sequence datasets and apply masks for padded sequences. Share metric-decoding logic across evaluation and inference.

11. **P2 — Modifier-click loses the accumulated node selection.**

    Source: [GraphCanvas.tsx:888](/Users/davidbachman/Documents/BackpropBuilder/src/components/GraphCanvas.tsx:888).

    React Flow's selection event can select two nodes, but the following node-click callback always replaces the selection with the clicked node. A Meta-click callback reproduction retains only `weight-1` instead of both selected IDs. This interferes with grouping and other multi-node operations.

    Fix: respect selection modifiers or let React Flow's selection-change callback own normal selection. Test the complete modifier-click event sequence.

12. **P2 — Code navigation does not move the camera for ungrouped graphs.**

    Source: [GraphCanvas.tsx:218](/Users/davidbachman/Documents/BackpropBuilder/src/components/GraphCanvas.tsx:218).

    Both semantic layout sources are absent when there are no groups. Node-focus requests return before moving the camera. A one-node ungrouped graph reproduction calls neither `setViewport` nor `fitView`; selecting an off-screen calculation from Code cannot bring it into view.

    Fix: fall back to React Flow node bounds or `fitView` with the requested node.

13. **P2 — Visually covered module contents remain keyboard-accessible.**

    Sources: [GraphCanvas.tsx:606](/Users/davidbachman/Documents/BackpropBuilder/src/components/GraphCanvas.tsx:606), [BuilderNode.tsx:119](/Users/davidbachman/Documents/BackpropBuilder/src/components/BuilderNode.tsx:119).

    The canvas disables pointer interaction and wrapper focus, but nested inputs and buttons remain active. A closed Linear module at zoom `0.1` still contains an enabled weight input with `tabIndex=0` and no inert ancestor. Keyboard users can reach and change controls they cannot see; those contents also remain exposed to assistive technology.

    Fix: apply `inert` and appropriate accessibility hiding to inaccessible node contents, restoring them when the node becomes accessible. Test focus traversal across closed and open modules.

**Test, deployment, and dependency follow-up**

- The existing failure at [App.test.tsx:316](/Users/davidbachman/Documents/BackpropBuilder/src/App.test.tsx:316) checks selection synchronously before a 650 ms camera transition reveals the node. The same interaction passes with `waitFor`. Fix the timing assertion; this is distinct from the ungrouped-navigation defect above.
- [deploy-pages.yml:29](/Users/davidbachman/Documents/BackpropBuilder/.github/workflows/deploy-pages.yml:29) installs and builds but does not run tests or lint. A passing build can therefore deploy known behavioral regressions. Add these gates; enable optional PyTorch parity in a separate job with a pinned Python environment.
- The saved full dependency scan reports 28 affected development packages (9 high, 18 moderate, 1 low), including transitive impact. An earlier response reported 10; the captured JSON is the later snapshot, and advisory counts should be rechecked when updating. `npm audit --omit=dev` reports zero. Counts are scanner findings, not confirmed exploitable paths in the static production app.
- Installed Vite 8.0.10 falls within the vendor's affected range for a Windows development-server file-deny bypass, patched in 8.0.16. Its stated exposure requires a network-exposed dev server and relevant Windows/NTFS conditions. [Vite advisory](https://github.com/vitejs/vite/security/advisories/GHSA-fx2h-pf6j-xcff).
- Installed Vitest 4.1.5 is also flagged for a mock-redirect file-read vulnerability. Update development dependencies and regenerate the lockfile through reviewed, compatible upgrades, then rerun build/lint/tests. [Vitest advisory](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9).

**Suggested repair order**

First protect workspace state from stale asynchronous results and correct tensor batch semantics. Next fix tensor decoding, projected edits, stale canvas callbacks, and stale reports. Then address the three export discrepancies, sequence metrics, selection/navigation, and keyboard accessibility. Add focused regression tests alongside each fix, stabilize the existing timing assertion, and gate deployment. Follow with synchronous-evaluation and dense-export optimization, then bundle/rendering improvements.
